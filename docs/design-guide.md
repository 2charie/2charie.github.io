# 디자인 가이드

## 1. 콘셉트
Editorial / Minimal / Paper-like. 따뜻한 아이보리 지면, 넓은 여백, 명확한 제목, 얇은 선을 중심으로 구성합니다. 프로젝트만 컨테이너 카드로 구분하고 역량과 연락처는 리스트로 유지합니다. 그림자, 그라데이션, 패럴랙스는 사용하지 않습니다.

## 2. 컬러
assets/css/variables.css의 토큰을 공통 기준으로 사용합니다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| --color-bg | #F8F7F3 | 기본 지면 및 헤더 |
| --color-surface | #EEECE6 | 카드, Hero 단색 배경, 필터 |
| --color-text | #171717 | 본문, 제목, 기본 버튼 |
| --color-muted | #77746E | 보조 설명 및 메타 |
| --color-line | #DEDCD5 | 구분선 |
| --color-white | #FFFFFF | 기본 버튼 및 선택 필터 텍스트 |
| --color-hover | #e7e4dc | 프로젝트 카드 호버 |

소문자/대문자 표기와 무관하게 동일한 색을 사용합니다. 별도 브랜드 강조색은 없습니다. 단색 SVG 4개의 중성색은 임시 이미지로만 사용합니다. 주요 정보는 --color-text로 표시합니다.

## 3. 타이포그래피
Pretendard 1.3.9를 CDN CSS로 불러오며 시스템 폰트로 폴백합니다. 외부 폰트 로딩 실패 시에도 화면은 유지됩니다.

| 요소 / 변수 | PC | 모바일 | 굵기 |
| --- | --- | --- | --- |
| H1 / --text-h1 | 64px | 40px | 700 |
| H2 / --text-h2 | 40px | 30px | 600 |
| H3 / --text-h3 | 26px | 22px | 600 |
| 본문 / --text-body | 16px | 16px | 400 |
| 보조 / --text-small | 14px | 14px | 400 |
| 메타 / --text-meta | 12px | 12px | 500 |

제목 행간 1.2, 본문 행간 1.6. 한글 제목은 keep-all과 overflow-wrap:anywhere를 함께 사용합니다. 상세 본문 소제목은 26px/22px을 사용해 긴 문서의 위계를 조절합니다. 작은 영문 섹션 라벨은 .eyebrow를 사용합니다.

## 4. 너비와 그리드
.container는 최대 1160px, 기본 좌우 32px, 모바일 20px입니다. Hero만 전체 너비이며 70vh(모바일 70svh), 최소 높이 PC 480px/모바일 420px으로 극단적으로 낮은 화면의 텍스트 잘림을 막습니다. 1024px 이상 프로젝트 2열, 그 미만은 1열입니다. 상세 페이지는 상단부터 본문과 이전·다음 탐색까지 공통 최대 너비 800px을 사용합니다(13절).

## 5. 간격
--space-1부터 --space-24까지 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 96px 토큰을 제공합니다. 주요 섹션 세로 패딩은 96px, 태블릿 72px, 모바일 56px입니다. 카드 간격은 기본 32px, 모바일 24px입니다.

## 6. 라운드와 선
카드 --radius-card 8px, 이미지 --radius-image 6px, 버튼 --radius-button 6px, 태그 --radius-tag 4px. 구분선은 1px solid var(--color-line). 그림자는 사용하지 않습니다.

## 7. 버튼
.button: 최소 높이 48px, 상하 12px/좌우 24px, 검정 배경과 흰색 글자. .button-secondary: 투명 배경, 얇은 테두리, 검정 글자. hover는 배경색 변경이며 focus-visible은 2px 검정 외곽선과 5px 간격입니다. 필터와 메뉴는 최소 44px 터치 영역입니다.

## 8. 프로젝트 카드
.project-card: 보조 배경, 패딩 24px(모바일 20px), 8px 라운드. 대표 이미지 4:3과 6px 라운드. 번호/임시 상태 → 제목 → 요약 → 분류 순서입니다. 카드 전체 링크를 사용하며 내부에 별도 링크를 중첩하지 않습니다. hover 시 배경이 미세하게 바뀌고 이미지가 1.025배 확대됩니다. 공통 렌더러는 main.js의 PortfolioUI.card입니다.

## 9. 헤더와 내비게이션
헤더는 sticky top:0, 높이 72px/모바일 64px, 하단 구분선입니다. 로고는 2charie. 텍스트입니다. 모바일 메뉴는 헤더의 일반 흐름 안에서 펼쳐져 본문을 덮지 않습니다. aria-expanded, aria-controls, 메뉴 이름을 갱신합니다. 링크 선택, 외부 클릭, Escape로 닫히며 Escape는 토글 버튼으로 포커스를 돌립니다. 넓은 화면으로 전환해도 열린 상태를 해제합니다.

## 10. 반응형
1024px 이상: 프로젝트 2열. 768–1023px: 프로젝트 1열, 상세 수행 유형·담당 역할은 값이 모두 있을 때 2열. 767px 이하: 작은 제목, 햄버거 메뉴, Contact 1열, 역량 목록은 번호와 제목 아래 설명으로 구성합니다. 필터는 줄바꿈 없는 내부 가로 스크롤입니다.

## 11. 인터랙션과 접근성
일반 전환은 --transition:200ms ease, 이미지 확대는 250ms입니다. 분류는 requestAnimationFrame으로 초당 28px 이동하며 hover, focus, 터치, 휠 조작 중 멈춥니다. 터치 종료 후 2초 동안 정지해 조작을 돕습니다. 명시적인 정지/재개 버튼도 제공합니다. 복제 그룹은 aria-hidden=true, 복제 버튼은 tabindex=-1이며 클릭으로는 필터링할 수 있습니다. 키보드 포커스는 원본 버튼을 화면에 보이도록 이동시킵니다. prefers-reduced-motion에서는 자동 이동과 전환을 중단하고 직접 스크롤을 유지합니다. 결과 개수는 role=status로 알립니다. 본문 건너뛰기 링크와 focus-visible을 유지합니다.

## 12. 데이터 및 콘텐츠 원칙
projects-data.js만으로 Home, 목록, 상세를 함께 관리합니다. 분류 16개의 정확한 명칭과 동등한 위계를 유지합니다. 실제 프로젝트가 준비될 때 임시 플래그, 제목, 이미지와 본문을 교체합니다. 빈 기본 정보와 본문은 제목까지 생략합니다. About은 사용자가 제공한 소개 문구를 그대로 사용합니다. 이메일은 실제 정보를 받기 전까지 생성하지 않습니다. 임의 경력, 성과, 숙련도, 개인정보를 추가하지 않습니다. 본문 블록 확장 규칙과 이미지 경로는 README를 참고하세요.

## 13. 프로젝트 상세 공통 시스템

### 구조와 정렬
`projects/detail.html` → `project-detail.js`가 모든 프로젝트를 같은 템플릿으로 렌더링합니다. 번호·상태, 제목, 부제·요약, 태그, 대표 이미지, 메타, 본문, 이전·다음 탐색은 `.detail-main`의 동일한 좌우 경계를 사용합니다. 상단과 본문 사이에 별도 컨테이너를 중첩하지 않습니다. 공통 규칙은 `assets/css/project-detail.css`에 모으며 상세 HTML에서 콘텐츠 컴포넌트 CSS 다음에 로드합니다. Home 및 목록의 1160px 컨테이너에는 영향을 주지 않습니다.

기본 최대 너비는 800px입니다. 한글 본문 가독성과 연구 표·기획 화면을 함께 고려한 값입니다. 문단에만 최대 70ch를 적용하고 왼쪽 정렬을 유지합니다. 이미지·표·그래프·다이어그램·수치 요약은 기본 컨테이너의 전체 폭을 사용합니다.

### 메타 정보
`type`(수행 유형)과 `role`(담당 역할)이 모두 있으면 첫 행을 `repeat(2,minmax(0,1fr))`로 똑같이 나눕니다. 하나만 있으면 전체 행을 씁니다. `tools`는 다음 전체 행에, `period`는 그 다음 전체 행에 표시합니다. 추가 정보는 `metadata: [{label:'항목명', value:'값'}]`로 등록하며 항상 독립된 전체 행을 사용합니다. 추가 항목이 기본 50:50 배치를 바꾸지 않습니다.

값은 앞뒤 공백을 정리하며 빈 문자열·null·undefined 및 빈 배열/공백만 있는 배열은 생략합니다. 추가 항목은 라벨도 있어야 합니다. 모든 값이 비어 있으면 `dl` 자체를 생성하지 않으므로 빈 행과 구분선도 없습니다. 라벨 12px/보조 색상, 값 16px/줄간격 1.75, 행·열 간격 24px을 공유합니다. 긴 URL·영문은 자연스럽게 줄바꿈하고 높이는 자동으로 늘어납니다.

### 본문 컴포넌트
- 섹션 제목은 h2, 내부 제목은 h3/h4 계층을 유지합니다. 섹션 h2는 기존 `--text-h3`(26px, 모바일 22px)를 재사용합니다. 섹션 간격 48px, 제목 아래 20px입니다.
- 본문 줄간격 1.75, 연속 문단 간격 16px, 목록·시각 자료·접이식 블록은 기본 24px 간격을 사용합니다. 세부 차트의 범례·축·수치 및 단계형 다이어그램 내부 배치는 해당 컴포넌트가 관리합니다.
- 이미지는 너비 100%/높이 auto로 원본 비율을 유지합니다. 대표 이미지 영역은 4:3, `object-fit:contain`으로 잘림을 막습니다.
- 표는 컨테이너 전체 폭을 사용합니다. 일반 데이터 표의 최소 너비는 기존 580px이며 `.table-scroll` 내부에서만 가로 스크롤합니다. `compact:true`는 최소 너비를 해제합니다. 스크롤 영역은 키보드 포커스와 접근 가능한 이름을 유지합니다.
- 이미지·그래프·표의 캡션은 14px/줄간격 1.6/보조 색상, 자료와 12px 간격을 공유합니다. 캡션이 앞에 있는 기존 그래프는 그 위치를 유지합니다.
- 링크는 밑줄과 포커스 표시를 유지합니다. 접이식 상세는 네이티브 details/summary와 기존 키보드 동작을 유지합니다. 수치 요약은 기존 컴포넌트의 반응형 그리드를 사용하고 바깥 너비·간격은 공통 규칙을 따릅니다.
- 이전·다음 탐색은 같은 컨테이너 안의 동일 너비 2열입니다. 긴 제목은 줄바꿈하고 없는 방향은 빈 자리만 유지합니다.

### 화면 크기와 토큰
기존 767px/1023px 브레이크포인트를 유지합니다. 데스크톱·태블릿에서 좌우 여백은 최소 32px, 767px 이하에서는 20px입니다. 모바일에서 메타는 모두 1열, 섹션 간격 40px, 페이지 하단 여백 64px입니다. 834px에서는 실제 콘텐츠 폭이 770px로 줄어듭니다. 표의 내부 스크롤 외에는 페이지 가로 스크롤을 만들지 않습니다.

| 토큰 | 값/참조 | 용도 |
| --- | --- | --- |
| `--detail-width` | 800px | 상세 공통 최대 너비 |
| `--detail-wide-width` | `--content-width` (1160px) | 선택적 확장 최대 너비 |
| `--detail-gutter` | `--space-8` / 모바일 `--space-5` | 화면 좌우 최소 여백 |
| `--detail-prose-width` | 70ch | 문단 최대 줄 길이 |
| `--detail-section-gap` | `--space-12` / 모바일 `--space-10` | 본문 상하·섹션 간격 |
| `--detail-block-gap` | `--space-6` | 본문 자료 간격 |
| `--detail-meta-column-gap` | `--space-6` / 모바일 `--space-4` | 메타 열 간격 |
| `--detail-meta-row-gap` | `--space-6` | 메타 행 간격 |
| `--detail-leading` | 1.75 | 본문·메타 값 줄간격 |

폰트 크기·색상·라운드·일반 간격은 기존 토큰을 재사용합니다. 모바일 토큰 재정의는 `.detail-main`에 한정합니다.

### 새 프로젝트와 확장 콘텐츠
`projects-data.js`의 projects 배열에 고유 id와 제목·요약·태그·이미지·메타·본문을 추가합니다. `sections:[{title,content}]` 또는 기존 overview/problem/process/results/reflection 필드를 사용할 수 있습니다. HTML/CSS 수정 없이 템플릿과 탐색이 적용됩니다.

넓은 비교 표·복잡한 대시보드·그래프처럼 800px을 넘어야 읽기 쉬운 자료에만 본문 블록의 `width:'wide'`를 지정합니다. 기본 문단이나 섹션 전체를 임의로 확장하지 않습니다. 확장은 최대 1160px이면서 화면 여백 안에 들어가도록 중앙 배치되며, 다음 일반 블록은 다시 기본 기준선을 사용합니다. 모바일에서는 기본 콘텐츠와 같은 폭으로 축소됩니다.

```js
metadata: [{ label: '협업 방식', value: '팀 프로젝트' }],
sections: [{ title: '비교', content: [
  { type: 'table', width: 'wide', caption: '비교 표',
    headers: ['항목', '내용'], rows: [['A', '설명']] }
] }]
```

금지: 프로젝트 ID별 너비·여백 보정, 마지막 메타 항목이라는 이유로 전체 행을 지정하는 선택자, 항목 순서에 의존한 열 배치, 본문에 임의 inline CSS/HTML 추가, `overflow-x:hidden`으로 오류 숨기기, 자료마다 새로운 페이지 컨테이너 만들기. 프로젝트별 CSS는 차트·데모 등 내부 시각화에 한정합니다.

검증 스크립트 `scripts/validate-detail.cjs`는 로컬 서버와 Playwright가 필요합니다. `PLAYWRIGHT_MODULE`/`CHROMIUM_PATH`로 설치된 런타임을 지정할 수 있습니다. 실제 데이터를 수정하지 않고 네트워크 응답을 가로채 예외 프로젝트를 추가하여 검사합니다. 결과와 스크린샷은 `output/playwright/detail-system-*`에 저장합니다.

## 14. Home About·Skills와 태그 연결
Home 순서는 Hero → Selected Projects → About → Skills → Contact입니다. About은 대학/현재 업무/배우고 있는 것의 세 구간입니다. 각 구간은 PC에서 1:1 그리드(간격 64px)이며 첫째·셋째는 이미지 왼쪽, 둘째는 이미지 오른쪽입니다. 모바일은 DOM 순서대로 모두 이미지→텍스트 세로 배치(간격 32px)합니다. 본문 줄간격 1.8, 제목 아래 간격 24px입니다. 구간 사이 여백은 위 구간 margin 24px + 다음 구간 padding 32px(구분선 포함 57px)입니다. 섹션 패딩은 PC 64px/모바일 48px입니다. 행 높이는 고정하지 않습니다. 텍스트는 keep-all로 단어 단위 줄바꿈하며 이미지와 세로 중앙 정렬합니다. 생성 이미지 3장은 assets/images/about에 1200×900 WebP로 저장하며 원본은 4:3/6px 라운드입니다. 이미지는 PC·모바일 모두 해당 열 너비 전체를 채우며 4:3 원본 비율을 유지합니다. 별도의 400px 최대 너비 제한은 사용하지 않습니다. 상세 프롬프트는 docs/about-images.md에 기록합니다.

Skills는 실제 a 태그 하나로 구성된 동일 크기 카드 5개입니다. 1024px 이상은 3+2개(아래 2개 중앙 정렬), 768–1023px은 2열, 767px 이하는 1열입니다. 최소 높이 200px, 패딩 24px, 카드 간격 24px이며 내용이 길면 높이가 늘어납니다. 상단은 30px Lucide 아이콘과 22px 제목을 12px 간격으로 가로 중앙 정렬합니다. 설명은 14px이며 상단에서 16px 아래에 표시합니다. 하단은 왼쪽 프로젝트 보기/오른쪽 화살표로 정렬합니다. 아이콘은 brain/panels-top-left/chart-column/cpu/sprout의 원본 경로를 inline SVG로 표시하며 24px viewBox/선 두께 1.5/둥근 끝처리를 통일합니다. 아이콘 배경은 없고 기본 보조색→상태 강조색을 적용합니다. 카드는 --color-white 배경과 1px 구분선, 호버·포커스에서 --color-surface 배경과 --color-text 테두리를 사용합니다. 이동·확대 없이 상태를 표시하며 키보드 포커스 외곽선을 유지합니다.

매핑: 심리학→심리학, 웹 기획→서비스 기획, 데이터 분석→웹 분석, 인공지능→인공지능, 스마트팜→스마트팜. href는 projects/index.html?tag=인코딩된값입니다. projects.js가 기존 choose/render를 통해 URL·버튼·목록·건수를 함께 갱신합니다. 사용자 필터 변경은 pushState, 초기화는 tag 제거, popstate는 URL에서 상태 복원입니다. 누락·잘못된 태그는 전체를 표시합니다.

## 15. Contact 모달
GNB Contact는 페이지 이동 링크 대신 dialog를 여는 button입니다. main.js가 모든 페이지에 동일한 네이티브 dialog를 생성합니다. Email과 GitHub는 PORTFOLIO의 공통 데이터를 사용하고 Home Contact의 Email도 동일한 값으로 렌더링합니다. 현재 이메일은 cksfl0214@gmail.com입니다.

모달은 최대 520px/좌우 최소 20px 여백, 기존 지면·선·라운드 토큰을 사용합니다. 제목 연결과 닫기 버튼 이름을 제공하며 네이티브 showModal로 배경 조작을 차단합니다. 모달을 열면 배경 스크롤을 잠그고 닫기 버튼으로 포커스를 이동합니다. 닫기 버튼·Escape·모달 바깥 클릭으로 닫으며, 데스크톱은 Contact 버튼/모바일은 닫힌 메뉴의 토글로 포커스를 돌립니다. 기존 Home #contact 직접 앵커 URL은 계속 지원합니다.
